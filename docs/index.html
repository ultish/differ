KSP writes the comparator. You keep the bits and the events.

Annotate the fields you care about. The processor emits a *Differ that compares two values of the same type. hasChanged is a bit test. changes holds only what moved, keyed by id, never by list position. The walk is ordinary generated Kotlin. No reflection, no JSON tree, no interpreter.

Why it is fast

You mark the fields that matter. At compile time KSP writes a *Differ of ordinary Kotlin ifs. There is no reflection at runtime, no JSON tree, no interpreter. hasChanged is a bit test. Old and new values are copied only for fields that moved. Nested lists and maps are matched by id, so a shuffle is not a change.

You can write that walk yourself. On our bench it is a bit faster. You then own every if, every bit, and every add/remove branch. A new field is another edit. A rename can silently drop a check. Differ regenerates the walk from the annotations. A tagged rename fails the build. The result still has the bits, the sealed events, and the keyed maps.

Both sides of a diff are the same Kotlin type. Convert Avro, Mongo, or a Kafka payload when it arrives. If stored ids are String and the event uses UUID, parse once at that boundary. The generated walk then does plain ==.

What you write

// same type on both sides
@Differ
data class Pet(
  val id: String,
  @Tracked val name: String,
  @Tracked(captureValues = false)
  val notes: String,
  @Tracked val nickname: String?,
  @TrackedNested val owner: Person,
  @TrackedNested val vet: Person?,
  @TrackedList val toys: Set<Toy>,
  @TrackedList val walks: List<Walk>,
  @TrackedMap val tricks: Map<String, Trick>,
  @TrackedMap val tags: Map<String, String>,
)
val diff = PetDiffer.diff(old, new)
if (!diff.hasChanged) return
if (diff.hasName) { /* bit test */ }

for (change in diff.changes) {
  when (change) {
    is PetChange.ToysName -> {
      change.id
      change.old
      change.new
    }
    is PetChange.Vet -> change.new
    else -> {}
  }
}

diff.tags["color"]?.value?.new

Child types do not take @Differ. Their tagged fields fold into the generated file. PetDiffer is the entry. PetDiffer.diff returns a PetDiff. The bits and events live on that result. A typo does not compile. A rename of a tagged property fails the build. A new untagged field is invisible. 

// generated. Do not edit. One hasX / event per tagged path.
object PetDiffer {
  fun diff(old: Pet, new: Pet): PetDiff
}

class PetDiff {
  val hasChanged: Boolean
  val hasName: Boolean
  val hasNotes: Boolean
  val hasNickname: Boolean
  val hasOwnerAge: Boolean
  val hasToysName: Boolean
  val hasToysAdded: Boolean
    // ...
  val changes: List<PetChange>
  val toys: Map<String, PetToysChange>
    // ...
}

sealed interface PetChange {
  data class Name(val old: String, val new: String)
  data object Notes
  data class ToysName(val id: String, val old: String, val new: String)
    // ...
}

Rules that matter

Lists, sets, and maps match by id (or map key), never by order. TreeSet and TreeMap count. null list or map is empty. Optional nested objects record presence. Both null is unchanged. One null is a single event with the whole object. Primitive arrays are not keyed collections. Mark them @Tracked and compare the whole array.
